Contexto del proyecto
Contexto
Un datacenter concentra servidores, redes y sistemas de climatización que deben operar sin interrupciones. Cualquier falla ambiental, de acceso o de trazabilidad de activos puede afectar la continuidad del servicio.
Problema
Hoy esa información vive repartida en planillas, bitácoras y en la memoria de las personas. No existe un registro único que muestre, en un mismo lugar, qué activo es, dónde está, quién entró y en qué condición ambiental se encuentra la sala.
¿Por qué SICMA?
Permite construir un sistema que registre activos, mida temperatura y humedad, controle accesos y alerte ante desviaciones antes de que se conviertan en incidentes. De un enfoque reactivo a uno preventivo.

Servicio central de datos

La lógica de SICMA vive en una API REST construida en Django, sobre Python. Expone los datos de activos, accesos, alertas y lecturas ambientales al resto del sistema.

Por qué Django: entrega autenticación, ORM y panel administrativo listos para usar, lo que acelera el desarrollo de un prototipo con varios módulos.

CAPA :: BACKEND
  • Python lenguaje
  • Django REST Framework API
  • Ubuntu Server despliegue

Sensores y control de campo

Un microcontrolador ESP32-S3 lee un sensor DHT22 y publica cada medición de temperatura y humedad a la API mediante HTTP.

Por qué ESP32-S3: conectividad Wi-Fi integrada y cómputo suficiente para leer sensores y enviar datos sin hardware adicional.

CAPA :: IOT
  • ESP32-S3 microcontrolador
  • DHT22 temperatura y humedad
  • HTTP POST cada 2 s frecuencia de envío

Interfaz para el equipo del datacenter

La aplicación se construye en Angular e Ionic, compartiendo un mismo código para la versión web y la aplicación móvil.

Por qué Angular + Ionic: un solo proyecto cubre escritorio y celular, útil para revisar alertas desde cualquier lugar.

CAPA :: FRONTEND
  • Angular framework web
  • Ionic empaquetado móvil
  • HTTPS REST consumo de API

Persistencia y despliegue

Los datos se almacenan en un clúster MySQL InnoDB con Group Replication, ejecutado junto al backend sobre Ubuntu Server.

Por qué un clúster: mantiene el sistema disponible aunque un nodo falle, algo relevante para un sistema que monitorea infraestructura crítica.

CAPA :: DATOS Y SERVIDOR
  • MySQL InnoDB Cluster 3 nodos
  • Ubuntu Server sistema operativo
  • Group Replication alta disponibilidad
Flujo de datos de punta a punta

El valor de SICMA no está solo en medir un datacenter,
sino en anticiparse a lo que le puede pasar.
LESSON.01
El alcance define la factibilidad
Priorizar un producto mínimo viable permitió comprometer un plan de cuatro incrementos realista para un equipo de tres personas.
LESSON.02
Simular antes de intervenir
Validar primero en un entorno simulado evita que las restricciones de un datacenter real bloqueen el avance del proyecto.
LESSON.03
La arquitectura reparte el trabajo
Dividir SICMA en capas de IoT, backend, frontend y datos permitió asignar responsabilidades claras a cada integrante.
